## 二、总体设计

### 配置双轨制 + 配置源单选框

| 轨 | 存哪 | 管什么 |
|---|---|---|
| 基础配置（永远走 Schema） | Koishi Schema `Config` | baseUrl / timeout / commandPrefix / imageTheme / colorMode / enableQuote / imageType / configMode 等简单项 |
| 高级配置（configMode=json 时启用） | `data/60s-vincentzyu/config/advanced-config.json` | 每命令渲染 override、globalDefault |

**决策 A 已确认**：baseUrl/timeout/imageTheme/colorMode 等基础项**永远走 Koishi Schema**（控制台管理体验好）；JSON 只存复杂的"渲染模式"配置（globalDefault + commandOverrides）。Schema 只剩 `configMode` 单选框作切换开关。

### 配置源单选框 `configMode`

```ts
configMode: Schema.union([
  Schema.const('schema').description('🧩 使用 Koishi 控制台配置（Schema）'),
  Schema.const('json').description('📄 使用插件 JSON 配置文件（webui 高级配置）'),
]).role('radio')
  .default('schema')
  .description('🎚️ 渲染配置来源：二选一。选择 Schema 则优先级表在控制台配置；选择 JSON 则读 data/60s-vincentzyu/config/advanced-config.json（可 webui 编辑）。')
```

### 渲染模式枚举（5 个）

```
qq-auto        🖥️ QQ 智能：QQ官方平台 list→qq-markdown，single→text，image→image；非QQ平台降级为 general-auto 行为
general-auto   📱 常规智能：list→image(puppeteer卡片)，single→text，image→image
text           纯文本
image          puppeteer 卡片图
qq-markdown    QQ 原生 markdown
```

### 优先级表语义（选中即用 + 硬跳过）

- 从上到下逐项硬匹配，第一项"环境可用"即短路执行
- 环境不满足（image 无 puppeteer / qq-markdown 非QQ平台 / 渲染抛异常）→ **硬跳过下一项，不降级**
- 表末尾自动追加 `text` 兜底

### 运行时合并优先级

```
每命令 override(advanced-config commandOverrides)  >  命令 -m/--mode 临时  >  全局默认  >  text 兜底
（configMode=schema 时全局默认=config.renderModePriority；configMode=json 时=advanced-config.globalDefault）
```

## 三、一期：渲染模式重构（纯后端逻辑，无 UI）

**目标**：`auto` 拆为 `qq-auto` + `general-auto`，软降级改硬跳过。

### 改动清单

**1. `src/config.ts`**
- `RENDER_MODE`：删 `AUTO`，加 `QQ_AUTO: 'qq-auto'`、`GENERAL_AUTO: 'general-auto'`
- `RENDER_MODE_NAMES` 同步
- `DEFAULT_RENDER_PRIORITY` → `[{ mode: 'general-auto', enabled: true }]`
- description 明确化：
  - `qq-auto`：`🖥️ QQ 智能：QQ 官方平台列表类优先 QQ 原生 markdown；在非 QQ 平台自动降级为 general-auto 行为。`
  - `general-auto`：`📱 常规智能：列表类优先 puppeteer 卡片图（需安装 puppeteer），未安装自动降级文本；QQ 平台同样适用。`
  - 优先级表总说明：`表格从上到下逐项硬匹配，第一项可用即短路；环境不满足的模式自动跳过，不会降级。`

**2. `src/render/dispatch.ts`**
- 删 `AUTO_KIND_MODE`，改为两个映射：
  ```ts
  const QQ_AUTO_KIND_MODE = { list: QQ_MARKDOWN, single: TEXT, image: IMAGE }
  const GENERAL_AUTO_KIND_MODE = { list: IMAGE, single: TEXT, image: IMAGE }
  ```
- `resolveMode` 改造：
  - `qq-auto`：QQ 官方平台 → 按 `QQ_AUTO_KIND_MODE[kind]` 解析；非 QQ → 按 `GENERAL_AUTO_KIND_MODE[kind]` 解析（就地降级为 gen 行为）
  - `general-auto` → 按 `GENERAL_AUTO_KIND_MODE[kind]` 解析
  - **删掉软降级** `IMAGE && !canUseImage → TEXT`、`QQ_MARKDOWN && !enableQQMarkdown → TEXT`
- `renderWithMode`：image 无 puppeteer / qq-markdown 非QQ平台 / 渲染失败 → 全部返回 `null`（硬跳过），不降级 TEXT
- `renderReply`：末尾 `priority.push({mode: TEXT})` 兜底保持不变

**3. `src/commands/helper.ts`**
- `parseModeOption` 扩展：接受 `qq-auto` / `general-auto`

**4. 测试**
- `test/helpers/setup.ts`：`renderModePriority` 默认改 `[{mode:'general-auto'}]`
- 新增 dispatch 测试：qq-auto 平台降级、general-auto 的 list→image 硬跳过、无 puppeteer 时 image→null→text 兜底

### 验收
- `yarn build` 无错；`yarn test` 全过
- 单测覆盖：qq-auto 非QQ降级 / general-auto list出图 / image无pptr硬跳过

## 四、二期：JSON 高级配置存储 + configMode 单选框

**目标**：`data/60s-vincentzyu/config/advanced-config.json` 存每命令渲染 override；新增 `configMode` 单选框切换配置源。

### 改动清单

**1. `src/config-storage.ts`（新增）** — 仿 ll-serverinfo `template.ts`
```ts
const CONFIG_ASSET_PARTS = ['data', '60s-vincentzyu', 'config', 'advanced-config.json'] as const
```
- `resolveConfigPath(ctx)`：`path.resolve(ctx.baseDir, ...CONFIG_ASSET_PARTS)`
- 校验：拒绝绝对路径片段 / `..`（复用零占用 v2 的 `resolveRelativePathUnderBaseDir` 模式）
- `loadAdvancedConfig(ctx)`：读 JSON，缺文件返回默认
- `saveAdvancedConfig(ctx, data)`：`mkdir -p` + 原子写（临时文件 + rename）
- 默认配置：
  ```json
  {
    "version": 1,
    "globalDefault": "general-auto",
    "commandOverrides": {}
  }
  ```

**2. `src/config.ts`** — 仿 ll-serverinfo `config.ts:377` 的展示型配置
```ts
advancedConfigPath: Schema.array(String)
  .role('table')
  .default([...CONFIG_ASSET_PARTS])
  .experimental()
  .disabled()
  .description('高级配置 JSON 相对路径（相对于 Koishi 根目录 ctx.baseDir），仅供查看')
```
同时加 `configMode` 单选框（见总体设计）。

**3. `src/index.ts` / `src/client.ts`**
- apply 时按 `configMode` 加载配置源：
  ```ts
  const renderSource = config.configMode === 'json'
    ? await loadAdvancedConfig(ctx)
    : { globalDefault: null, overrides: {} }  // schema 模式走 config.renderModePriority
  ```
- 每个命令 action 合并：`commandOverrides[commandName]?.renderMode` > `-m` > 全局默认
- 提供 `client.getRenderMode(commandName, options.mode)` 统一入口

**4. 测试**
- config-storage：读写、默认值、非法路径报错、原子写
- 合并逻辑：override > -m > 全局表（两种 configMode）

### 验收
- 手写 JSON 可控制单命令渲染
- 非法/绝对路径被拒绝
- `configMode=json` 时命令 override 生效，`-m` 仍最高优先
